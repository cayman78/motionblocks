# Glossary

## Stofendez Lab

The project laboratory / team brand.

## MotionBlocks

The main project.

A wearable motion intelligence system that collects, labels, stores, analyzes, and later classifies human motion patterns.

Current hardware target:

```text
M5StickC Plus2
```

Current working mode:

```text
wearable device → Wi-Fi → HTTP logger → CSV files → metadata
```

---

## MotionLink

Future technology layer for linking the personal motion domain to external dashboards and Human-by-Wire domains.

In the current prototype, MotionLink is only a future concept.  
The current working transport is Wi-Fi HTTP logging.

---

## Human-by-Wire

A broader architectural idea where human-related domains can be represented as connected digital domains.

MotionBlocks may later become a personal motion domain inside this architecture.

---

## Motion block

A labeled motion pattern.

Examples:

```text
idle
walking
standing up
sitting down
jumping
shaking hand
fall-like event
unusual motion sequence
```

Motion blocks are the future semantic units for comparison, classification, and pattern recognition.

---

## Motion domain

A personal domain that owns and processes motion-related data, metadata, events, and derived features.

In the current prototype, the motion domain is represented by:

```text
raw CSV files
metadata JSON files
future feature files
```

---

## Experiment

A logical data collection activity.

Example:

```text
EXP01 — ordinary home movements
```

An experiment groups devices, sessions, subjects, movements, and metadata.

Current metadata file:

```text
data/metadata/experiments.json
```

---

## experiment_id

A short technical identifier for an experiment.

Examples:

```text
EXP01
EXP02
EXP03
```

The human-readable name of the experiment is stored separately in metadata fields such as:

```text
short_name
title
goal
comments
```

---

## Device

A physical sensor device used for recording motion.

Current device:

```text
M5StickC Plus2
```

Example device id:

```text
m5_001
```

---

## device_id

A technical identifier assigned outside the firmware by the logger or metadata layer.

Example:

```text
m5_001
```

The firmware currently does not know `device_id`.

---

## Recording session

A group of records collected under one session id.

In the current firmware, sessions are controlled by Button B.

Examples:

```text
A001
A002
A003
```

Each session normally corresponds to one raw CSV file:

```text
data/raw/EXP01/m5_001/session_A001.csv
```

---

## session_id

A short session identifier generated by the device.

Examples:

```text
A001
A002
A003
```

The device knows `session_id`.

---

## session_uid

A globally unique session identifier used in metadata.

Current format:

```text
[experiment_id]_[device_id]_[session_id]
```

Example:

```text
EXP01_m5_001_A001
```

---

## Record

One recorded attempt inside a recording session.

In the current firmware, a record starts when Button A is double-clicked and stops when Button A is clicked during recording.

Current field:

```text
record_id
```

Important distinction:

```text
RecordingSession → contains one or more Records
Record → contains many MotionSamples
```

---

## record_id

A numeric identifier of a record inside a session.

Example:

```text
1
2
3
```

When the session changes, `record_id` resets to `1`.

---

## Motion sample

One timestamped IMU measurement row inside a record.

Current fields include:

```text
sample_id
device_timestamp_ms
ax
ay
az
gx
gy
gz
acc_norm
```

---

## sample_id

A numeric identifier of a sample inside a record.

It increments while recording is active.

---

## IMU

Inertial Measurement Unit.

A sensor block that includes:

```text
accelerometer
gyroscope
```

Current IMU fields:

```text
ax
ay
az
gx
gy
gz
```

---

## Accelerometer

Sensor that measures acceleration along device axes.

Current acceleration fields:

```text
ax
ay
az
```

Units:

```text
g
```

In rest position, the accelerometer still measures gravity.

---

## Gyroscope

Sensor that measures angular velocity around device axes.

Current gyroscope fields:

```text
gx
gy
gz
```

Units:

```text
deg_per_sec
```

---

## acc_norm

Derived acceleration magnitude.

Formula:

```text
acc_norm = sqrt(ax*ax + ay*ay + az*az)
```

In rest position, `acc_norm` should be close to:

```text
1.0 g
```

This metric is useful because it is less sensitive to device orientation than individual acceleration axes.

---

## Serial logger

Python tool for wired logging over USB Serial / COM port.

Current file:

```text
tools/serial_logger.py
```

Typical command:

```powershell
python tools/serial_logger.py --port COM6 --experiment-id EXP01 --device-id m5_001 --create-metadata
```

Status:

```text
working / useful for debugging
```

---

## HTTP logger

Python tool for wireless logging over Wi-Fi HTTP.

Current file:

```text
tools/http_logger.py
```

Typical command:

```powershell
python tools/http_logger.py --host 0.0.0.0 --port 8080 --experiment-id EXP01 --device-id m5_001 --create-metadata
```

Status:

```text
working / main path for wearable recording
```

---

## HTTP endpoint

A URL path exposed by the HTTP logger.

Current endpoints:

```text
GET  /health
POST /line
```

`GET /health` checks whether the logger is alive.

`POST /line` receives one MotionBlocks protocol line from the device.

---

## LOGGER_URL

Firmware configuration value pointing to the Python HTTP logger endpoint.

Example:

```cpp
#define LOGGER_URL "http://192.168.8.129:8080/line"
```

It is stored in local `wifi_config.h`.

---

## wifi_config.h

Local firmware configuration file containing real Wi-Fi credentials and logger endpoint.

Current path:

```text
firmware/m5stickc-plus2/src/wifi_config.h
```

Contains:

```cpp
WIFI_SSID
WIFI_PASSWORD
LOGGER_URL
```

This file must not be committed to Git.

---

## wifi_config.example.h

Version-controlled example of Wi-Fi configuration.

Current path:

```text
firmware/m5stickc-plus2/src/wifi_config.example.h
```

Used as a template for local `wifi_config.h`.

---

## MotionBlocks protocol

Simple line-based protocol sent by the firmware through Serial and HTTP.

Current lines:

```csv
EVENT,NEW_SESSION,session_id,timestamp_ms
EVENT,START,session_id,record_id,timestamp_ms
DATA,session_id,record_id,sample_id,timestamp_ms,ax,ay,az,gx,gy,gz,acc_norm
EVENT,STOP,session_id,record_id,timestamp_ms,sample_count
```

The protocol is intentionally stable across transports.

---

## EVENT row

A protocol row describing a recording event.

Current event types:

```text
NEW_SESSION
START
STOP
IMU_NOT_UPDATED
```

EVENT rows are stored in the same CSV files as DATA rows.

---

## DATA row

A protocol row containing one IMU sample.

Current DATA format:

```csv
DATA,session_id,record_id,sample_id,timestamp_ms,ax,ay,az,gx,gy,gz,acc_norm
```

---

## Raw CSV

The current raw data storage format.

Current path convention:

```text
data/raw/[experiment_id]/[device_id]/session_[session_id].csv
```

Example:

```text
data/raw/EXP01/m5_001/session_A001.csv
```

CSV is used because it is easy to inspect, plot, and explain.

---

## Metadata

Human-readable JSON files that describe experiments and recording sessions.

Current metadata files:

```text
data/metadata/experiments.json
data/metadata/recording_sessions.json
```

Metadata stores semantic information that the firmware does not know:

```text
subject_id
movement_type
movement_label
location
comments
status
tags
```

---

## Draft metadata

Metadata records automatically created by the logger when `--create-metadata` is enabled.

Draft metadata status:

```text
auto created. needs description.
```

Draft records should later be reviewed and completed manually.

---

## Subject

A person or object wearing or carrying the device during a recording.

Use aliases, not real names.

Examples:

```text
child_01
child_02
adult_01
```

---

## subject_id

Technical identifier of the subject.

Stored in metadata, not in firmware.

---

## movement_type

Controlled movement category.

Examples:

```text
idle
walking
jumping
shaking
fall_like
unknown
```

Stored in metadata.

---

## movement_label

More specific human-readable label for the movement.

Examples:

```text
standing_idle
walking_normal
jumps_basic
hand_shaking
sitting_to_standing
```

Stored in metadata.

---

## Data status

Metadata field describing the current state of a data record.

Examples:

```text
auto created. needs description.
raw
checked
processed
bad
test
archived
```

---

## Generated data

Local data created by loggers and analysis scripts.

Examples:

```text
data/raw/
data/processed/
data/features/
data/metadata/
data/db/
```

Generated data should normally be ignored by Git unless intentionally added as examples.

---

## Sampling rate

Frequency of IMU data collection.

Current default:

```text
10 Hz
```

Future modes:

```text
25 Hz   — normal educational motion recording
50 Hz   — fall-like events and sharper movements
100 Hz  — experimental / research mode
```

---

## Feature

A derived value calculated from raw motion samples.

Examples:

```text
acc_norm_max
acc_norm_mean
acc_norm_std
gyro_norm_max
record_duration
sample_count
```

Features should be computed later in Python analysis scripts.

---

## Experimental IMU-only displacement feature

Future experimental feature based on approximate trajectory reconstruction from IMU data.

Examples:

```text
estimated_path_length
estimated_displacement_norm
estimated_vertical_displacement
vertical_drop_score
```

These are not reliable physical coordinates.  
They may be useful as weak features for fall-like classification.

---

## Rapid Insight Layer

A first-stage analysis layer based on external tools such as:

```text
Edge Impulse
ChatGPT Data Analysis
Orange Data Mining
```

This layer is useful for quick experiments and intuition.

---

## Engineering Layer

The project’s own implementation of:

```text
data processing
feature extraction
modeling
evaluation
metadata management
```

This layer should grow gradually after real datasets are collected.

---

## FDAM compatibility

The current structure is simple but should remain compatible with a future FDAM-style motion domain.

Current practical hierarchy:

```text
Experiment
  → RecordingSession
      → DataFile
      → MotionRecord
          → MotionSample
              → Sensor values / channels
```

Children should not be exposed to FDAM concepts directly.
