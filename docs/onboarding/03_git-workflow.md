# Работа с Git

Этот документ описывает как мы работаем с Git в проекте MotionBlocks — структуру веток, правила коммитов и типичный рабочий процесс.

---

## Структура веток

```text
main        стабильная версия проекта
  └── dev   рабочая ветка команды
        └── feature/*   ветки для конкретных задач
```

**main** — защищённая ветка. Сюда попадает только проверенный код. Merge в main делает только владелец проекта.

**dev** — основная рабочая ветка. Здесь собираются изменения от всех участников. От неё создаются рабочие ветки, в неё делается merge после завершения задачи.

**feature/*** — ветки для конкретных задач. Создаются от `dev`, вливаются обратно в `dev`.

---

## Первый раз — получить ветку dev

После клонирования репозитория у тебя есть только `main`. Переключись на `dev`:

```powershell
git checkout dev
```

Убедись что ветка актуальна:

```powershell
git pull origin dev
```

---

## Типичный рабочий процесс

### 1. Начинаешь новую задачу

Убедись что находишься на `dev` и она актуальна:

```powershell
git checkout dev
git pull origin dev
```

Создай ветку для задачи:

```powershell
git checkout -b feature/название-задачи
```

Примеры названий:

```text
feature/add-jump-recordings
feature/fix-motion-browser
feature/fft-features
```

### 2. Работаешь над задачей

Вноси изменения в файлы. Периодически сохраняй прогресс коммитами:

```powershell
git add .
git commit -m "Описание что сделано"
```

Отправляй ветку на GitHub:

```powershell
git push origin feature/название-задачи
```

### 3. Задача готова

Убедись что в `dev` нет новых изменений которые надо подтянуть:

```powershell
git checkout dev
git pull origin dev
git checkout feature/название-задачи
git merge dev
```

Если конфликтов нет — отправь ветку на GitHub и сообщи владельцу проекта что задача готова к merge в `dev`.

---

## Правила коммитов

Коммит — это сохранённый снимок изменений. Хорошее сообщение коммита объясняет **что** сделано, а не как.

**Хорошо:**
```text
Add 10 jump recordings for child_01
Fix motion browser delete button
Add acc_norm_std to feature extraction
```

**Плохо:**
```text
fix
changes
wip
update files
```

Коммить часто — лучше много маленьких коммитов чем один огромный в конце.

---

## Получить обновления от других участников

Если кто-то добавил новые данные или изменения в `dev`:

```powershell
git checkout dev
git pull origin dev
```

---

## Что нельзя делать

- **Не пушить напрямую в `main`** — это защищено технически
- **Не пушить напрямую в `dev`** — только через feature ветки (договорная дисциплина)
- **Не коммитить `wifi_config.h`** — там пароли от WiFi, файл в `.gitignore`

---

## Полезные команды

```powershell
git status                    # что изменилось
git log --oneline -10         # последние 10 коммитов
git branch                    # список веток
git checkout название-ветки   # переключиться на ветку
git diff                      # посмотреть изменения до коммита
```

---

## Как попасть в проект

Сейчас ты можешь клонировать репозиторий и читать код. Чтобы пушить изменения:

1. Зарегистрируйся на GitHub если нет аккаунта
2. Сообщи свой GitHub username владельцу проекта
3. Получи права Collaborator
4. После этого `git push` будет работать
