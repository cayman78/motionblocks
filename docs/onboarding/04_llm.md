# Работа с LLM

LLM (Large Language Model) — языковые модели вроде Claude или ChatGPT — отличные помощники в разработке. Они помогают писать код, разбираться в ошибках, объяснять концепции и генерировать идеи.

Но у них есть особенность: **они не знают твой проект**. Каждая новая сессия начинается с чистого листа. Чтобы LLM помогал эффективно — ему нужно дать контекст.

---

## Какие файлы загружать

Для большинства задач достаточно:

```text
README.md                       общее описание проекта
docs/onboarding/01_setup.md     окружение и стек
docs/onboarding/02_hardware.md  устройство и протокол
```

Для задач по данным и ML добавь:

```text
docs/onboarding/03_data.md
```

Для задач по Git:

```text
docs/onboarding/04_git-workflow.md
```

Для задач по firmware — добавь сам файл который правишь:

```text
firmware/m5stickc-plus2/src/main.cpp
```

Для задач по Python инструментам — добавь нужный скрипт:

```text
tools/http_logger.py
tools/compute_features.py
tools/motion_browser.py
```

**Правило:** загружай только то что нужно для конкретной задачи. Лишний контекст не помогает — он замусоривает сессию.

---

## Стартовый промпт

Используй этот шаблон в начале сессии:

```
Я работаю над проектом MotionBlocks — носимое устройство для записи
и классификации движений человека. Устройство M5StickC Plus2 (ESP32),
прошивка на Arduino/FreeRTOS, данные передаются по WiFi на Python логгер,
сохраняются в CSV, анализируются в Orange и scikit-learn.

Я загрузил контекст проекта. Прочитай его перед ответом.

Моя задача: [опиши что хочешь сделать]
```

## Типичные задачи и как их формулировать

### Разобраться в ошибке

```
Вот ошибка которую я получаю:
[вставь полный текст ошибки]

Вот код где она происходит:
[вставь код]

Что не так и как исправить?
```

### Написать новую функцию

```
Мне нужно добавить в tools/compute_features.py функцию которая
вычисляет доминантную частоту через FFT для каждой оси.
Входные данные: столбцы ax, ay, az из CSV.
Выходные данные: три новых признака fft_dominant_freq_ax, ...
```

### Разобраться в чужом коде

```
Объясни что делает этот код и как он работает:
[вставь код]
```

### Отладить firmware

```
Устройство ведёт себя не так как ожидается: [опиши поведение].
Вот relevant часть main.cpp: [вставь код].
Что может быть причиной?
```

## Что LLM делает хорошо

- Объясняет код и концепции
- Находит ошибки и предлагает исправления
- Пишет boilerplate код по описанию
- Помогает разобраться в документации библиотек
- Генерирует варианты решения и объясняет trade-offs

## Что LLM делает плохо

- Не знает актуальное состояние твоего проекта без контекста
- Может уверенно написать код который не работает — всегда проверяй
- Не знает что именно у тебя на экране или в терминале
- Может путаться в деталях специфичных для конкретной версии библиотеки

---

## Практический совет

Если LLM даёт неправильный ответ — скорее всего ему не хватает контекста. Добавь нужный файл или уточни детали. Хорошо сформулированный вопрос с конкретным контекстом даёт намного лучший результат чем общий вопрос.
